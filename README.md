# SE Workflow · 第 11 组：设计规格驱动的任务分解与编排

软件管理与项目实践（SE2026B）课堂作业 2。
我们在完整软件开发流程中负责 **“设计之后、实现之前”** 这一段：

> 设计规格 → 任务分解 → 编排 → 执行可视化

给一份 `design spec`，由 PM Agent 拆成可验收的开发任务，再由编排器生成执行计划，
并把任务状态、门禁检查、人工卡点与异常恢复可视化出来。

---

## 怎么用（约 1 分钟）

1. 点 **「导入规格文件」**，选 `specs/` 里的样例（也可以直接在左侧改文字）
2. 点 **「① PM Agent 拆任务」** —— 左侧规格被拆成 13 个任务，每个任务带责任人、前置、优先级
3. 点 **「② 生成编排」** —— 右侧出现依赖图；日志输出“13 个任务、14 条依赖，没有环”
4. 点 **「③ 开始执行」** —— 灰（未开始）→ 蓝（进行中）→ 绿（完成）；每条“门禁通过”是一次校验
5. 黄色节点是 **人工卡点（HITL）**，点“人工确认，继续”才往下走
6. 点 **「注入一次异常」** —— 任务变红、写清原因；点“重试阻塞任务”恢复
7. 跑乱了按 **F5** 刷新即可重置

两个版本的差别：`index.html` 纯规则、不联网，最稳；`llm.html` 多一个下拉框，
可以选「调用大模型」（OpenAI 兼容接口，需填地址/模型/Key）或「模拟模型返回」（离线演示）。
两者调度与校验规则完全一致。

## 设计要点

1. **执行与校验分离**：任务跑完只说明产出有效，是否通过由门禁判断，
   避免格式合格但内容不完整的产出被放行。
2. **人工环节不设默认值**：需要人决定的地方必须有人明确回答，超时保持等待，不自动通过。
3. **异常不被掩盖**：失败、阻塞与版本变更都写入事件日志，下游不会因上游失败而被误判为完成。

编排器的判断全部写成有序规则（就绪五条件、G0–G5 门禁、分歧三分流、退出与降级），
同样输入必须得到同样结果，便于事后追溯。
